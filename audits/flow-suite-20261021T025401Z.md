# Renderflow implementation, qualification and roadmap audit

[Complete roadmap](https://github.com/egohygiene/renderflow/issues/367) · [Audit publication PR](https://github.com/egohygiene/renderflow/compare/main...audit/flow-suite-20261021T025401Z) · [Normalized evidence receipt](flow-suite-20261021T025401Z.json)

## Decision supported by this audit

Renderflow has substantial authored contracts and implementation. The next useful step is to recover a reviewable qualification baseline, publish the bounded first integration candidate through #419, and work through the existing creative/composition acceptance records without expanding that first release into every optional feature. This is a source and existing-evidence assessment, not a statement that current main compiles, tests pass, native applications accept its outputs, or a release exists.

At the frozen snapshot there are **25 open issues, including existing roadmap #367**, and one draft PR, #455. Thus the original ledger contains **24 work issues plus its roadmap**. All remain valid and open. No issue deletion, closure, merge, source implementation change or product execution belongs to this audit. Two focused gap issues are recommended: current qualification-baseline restoration and current contributor/architecture-document accuracy. Existing issues already own the larger provider, fixture, release, optional-AI and future-audit outcomes.

The first publication boundary is finite: explicitly ordered immutable PNG/JPEG pages through the declared print-interior PDF/fixed-layout EPUB contracts, an exact reviewed Linux x86_64 candidate, downloaded-byte/clean-install evidence, and an immutable manifest a Flow-owned adapter can pin. Closed #415–#418 record the preceding implementation checkpoints. That history does not make the newly audited source green or published. Full creative forests, broad localization, HTTP delivery, AI summaries, Sonic DNA, presentations and podcasts remain visible work, with independent product value and separate proof.

## Authority, scope and methods

The assessment follows Aether's approved auditor specification 2.0.0 and audit-repository procedure 1.1.0 at immutable revision `dc8a16851f452763ef4f7fbe4bf057d4500b1921`, plus the issue-authoring and read-only continuity guidance. Repository inventory found no tracked root/scoped `AGENTS.md`, `CONTINUITY.md` or `SECURITY.md`; the absence is a context limitation, not an invented local requirement or authorization to adopt new org policy. Existing architecture documents, handoffs, issue histories and workflows supply the local context. Historical audit logs were inventoried and the July production-readiness audit was sampled as historical context; its v0.2.1 findings are not silently treated as current defects.

The inventory covers 741 tracked files, three Rust workspace crates, version `0.3.0-rc.1`, edition 2021 and declared Rust 1.94. Inspection included repository/product documentation and architecture entry points; all open issue bodies and available issue comments; relevant closed foundation/publication/baseline issues; PR #455's body/file inventory and selected high-risk integration/codec/evidence diffs; Cargo manifests and relevant lock records; CI, conformance and release workflow contracts; planning/execution/forest/cycle selection; artifact storage/checkpoint/evidence boundaries; bounded external-process policy; optional AI skill execution; composition/creative qualification handoffs; and representative positive/negative conformance sources and fixture runners.

This is targeted source review across the full inventory, not a line-by-line claim for every Rust module or a native interoperability audit. The 231 Rust files, all dependency internals, every legacy template, all platform packages and every historical audit finding were not exhaustively requalified. Optional tools, model weights, external accounts and actual media/publication consumers were not invoked. No private artwork, lyrics, model prompt corpus was accessed.

The maintainer's explicit implementation-sprint qualification deferral remains effective. **No Renderflow tests, compiler/build/Cargo resolution, product format/lint checks, schema qualification, native/CLI/SDK/provider/visual runs, installations or new CI dispatch/reruns were performed.** Authored tests remain authored tests. Existing exact-source hosted records were read as evidence; this did not resume qualification. Local checks apply only to Git identity and the audit artifacts' structure, completeness, links/privacy and preservation of original issue text. Audit publication must preserve the existing `[skip ci]` boundary.

## Findings

### AUDIT-001 — Current Rust qualification stops before product tests

**Classification:** confirmed defect. **Severity:** medium. **Confidence:** high. **Status:** confirmed; remediation unresolved. **Area:** schema construction/qualification. **Effort:** small for source correction; later qualification bounded separately. **Impact:** medium — candidate binary/build evidence unavailable.

**Observation/evidence:** [spec.rs](https://github.com/egohygiene/renderflow/blob/81088f01b14c010e7dc6523763771f8461ed9b09/crates/renderflow-core/src/spec.rs) has stream-index schema maxima `4294967295` at lines 2363 and 2408. Existing Rust 1.94 logs report inferred overflowing `i32` literals. The Clippy gate also identifies 22 lint errors, while installer compilation reports the same two compiler failures. This gives a concrete counterexample to any current-main build/test-green claim.

**Recommendation/validation:** use a numeric representation that preserves the intended unsigned range, reconcile meaningful lint failures without weakening the gate, then run the declared exact-source/MSRV workflow when qualification resumes. **Coverage:** proposed [#458](https://github.com/egohygiene/renderflow/issues/458) is the focused owner; #419 remains the broader release gate. **Dependencies/risks:** full completion is qualification-gated. This is a new October baseline, not a reopening of closed September #407. Compiler failures do not prove the installer implementation or any unexecuted test is defective.

### AUDIT-002 — Locked corpus cannot begin

**Classification:** confirmed defect. **Severity:** medium. **Confidence:** high for the failure, unverified for its exact dependency delta. **Status:** confirmed; remediation unresolved. **Area:** dependency reproducibility. **Effort:** small estimated; exact resolution remains unknown. **Impact:** medium — locked conformance evidence unavailable.

**Observation/evidence:** the exact-source maximal corpus job invokes `cargo test --package renderflow --test golden_conformance --locked` and exits because the lock requires updating. #406's [handoff](https://github.com/egohygiene/renderflow/blob/81088f01b14c010e7dc6523763771f8461ed9b09/docs/work/406/HANDOFF.md) already says metadata-authored lock additions need the later Cargo gate. Presence of pinned entries in Cargo.lock does not establish a resolved graph.

**Recommendation/validation:** when execution resumes, obtain the Cargo-produced delta, explain any unexpected movement and retain `--locked` in conformance/release gates. Do not guess the exact culprit, hand-author another resolution or remove the flag. **Coverage:** [#458](https://github.com/egohygiene/renderflow/issues/458); later qualification remains within #406/#429/#430/#419 as applicable. **Dependencies/risks:** deferred Cargo execution; no claim that the entire corpus failed a behavioral assertion.

### AUDIT-003 — Optional Snap template does not select a workspace package

**Classification:** confirmed defect. **Severity:** low. **Confidence:** high. **Status:** confirmed; remediation unresolved. **Area:** optional packaging. **Effort:** small. **Impact:** low — current aggregate CI/package gate; no established published-channel outage.

**Observation/evidence:** [snapcraft.yaml](https://github.com/egohygiene/renderflow/blob/81088f01b14c010e7dc6523763771f8461ed9b09/snap/snapcraft.yaml) uses the Rust plugin at `source: .`; the root Cargo manifest is virtual. The existing job reports `cargo install` requires an actual package. It also meets AUDIT-001's compiler errors, so correcting only package selection is insufficient.

**Recommendation/validation:** select the workspace CLI package or an explicit equivalent install path and later run its declared check. Retain the recipe's unpublished-template status. **Coverage:** [#458](https://github.com/egohygiene/renderflow/issues/458) includes this small baseline prerequisite; #419 owns honest distribution truth. **Dependencies/risks:** executable qualification deferred. This is not a demand to publish Snap or broaden the initial Linux tarball candidate into every package channel.

## Positive observations and meaningful limits

The source already addresses much of the architecture discussed in older audits. [Derivative-path selection](https://github.com/egohygiene/renderflow/blob/81088f01b14c010e7dc6523763771f8461ed9b09/crates/renderflow-core/src/graph/derivative_path.rs) rejects repeated formats, validates finite edge costs/quality, enforces hop/candidate/loss bounds and deterministic ties, and preserves optimization-first targeted requests. [DAG execution](https://github.com/egohygiene/renderflow/blob/81088f01b14c010e7dc6523763771f8461ed9b09/crates/renderflow-core/src/graph/dag_executor.rs) validates graph structure before transforms, records cancellation/unreachable branches and uses compatible checkpoints with output verification. Representative regressions describe reversible-cycle and missing-provider counterexamples. These are substantive authored mechanisms; deferred tests mean their current executable behavior remains unproven here.

The forest publication join uses target identity, terminal inventory index, artifact identity and locator, not merely a digest or an expected output path. It distinguishes planned, published, not published, excluded and unavailable work. [The Flow handoff](https://github.com/egohygiene/renderflow/blob/81088f01b14c010e7dc6523763771f8461ed9b09/docs/architecture/flow-artifact-forest.md) explicitly requires downstream path confinement/digest verification, preserves loss/review state and distinguishes common projections from authoritative native receipts. Cross-suite static review found the minimal `to_flow_v1` field shape compatible with frozen Flow's schema; it intentionally omits native publication/locator/validation/review detail and includes general inventory. It must not be mistaken for a selected approved deliverable set or released integration. Flow #52 already owns the adapter and #419 the immutable release; no new cross-suite defect was confirmed.

Creative and composition handoffs are unusually clear about source-only status. #429 distinguishes discovery observations from exact executable/package/model/font identities; an observed PATH version is not attestation or provider qualification. Composition uses shared CLI/SDK admission and retains native locale/output contracts rather than forcing multiple locale identities through a format-keyed DAG. Its bounded Latin typography, opaque raster/PDF profile, explicit writing-mode refusals and review-required outputs are documented. Broader fidelity, complete process RSS limits, print acceptance and native application editability remain separate proof, already covered by #406 and the creative children.

The [AI runtime](https://github.com/egohygiene/renderflow/blob/81088f01b14c010e7dc6523763771f8461ed9b09/crates/renderflow-core/src/ai/runtime.rs) already separates model resolution, explicit exposure/remote policy, structured schema-bound output, budgets/hygiene, provenance and review-required candidate state. #456 is a bounded consumer of that infrastructure, not justification for another model router. Its grounding tests must demonstrate claims against exact source spans; a schema-valid mock is not evidence of local model quality. #397 retains distinct analyzer/lyrics/transcript/MIDI authority and Aniflow temporal ownership. Optional AI remains independent of deterministic publication.

PR #455, head `eb47f6331cf3f81868b3566521976484349a64b9`, is a separate **draft, unmerged, unqualified** checkpoint. It authors original-Fountain direct body exports and canonical transcript-to-terminal Text, with explicit opt-in, original/canonical/output reconstruction, unqualified review state and disabled native reuse. It does not enable rejected Scripttool reverse routes or expand recovery's accepted target contract. Native-only bundles retain canonical companions in local artifact storage unless selected for publication. The branch predates main's ADR renumbering, so its base-to-main difference also includes historical DECISIONS.md drift. This audit neither merges that branch nor treats its exports as main/released support; #430 already owns review, integration and actual proof.
