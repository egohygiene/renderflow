# Afterwriting provider evaluation — Renderflow #425

Source review date: 2026-10-12. This evaluates optional external afterwriting
source, not runtime qualification. No packages, runtimes, fonts, or executables
were installed or downloaded for execution. No tests, builds, linting, schema
validation, provider runs, or CI jobs were run.

## Decision

Adopt an **authored, unqualified, explicit opt-in Fountain → screenplay PDF
candidate** behind Renderflow's bounded provider boundary. Independently validate
the accepted screenplay subset and produced PDF. Keep source semantics separate
from provider formatting. Process success alone does not establish valid PDF,
preserved text, good typography, full Fountain support, or reproducible bytes.

| Candidate | Checkpoint decision | Evidence |
| --- | --- | --- |
| Fountain → PDF | Narrowly adapt; defer runtime qualification | Concrete CLI PDF contract and a controlled settings file. |
| Direct FDX → PDF | Reject | Upstream explicitly lists direct CLI FDX conversion as a known issue. |
| OSF, Fade In, or canonical screenplay JSON input | Reject | Not supported inputs in the reviewed CLI contract. |
| Provider statistics / analysis JSON | Reject | No CLI report flag or stable JSON serialization contract. |
| Arbitrary custom fonts or settings | Reject | Fonts load as executable JavaScript; settings can suppress or replace source content. |
| Byte-identical reproduction | Not claimed | No CLI date/ID controls and no two-run qualification. |

The checkpoint's analysis is computed by Renderflow from independently parsed
ASCII body content: element counts, ordered scene headings, and exact character
cues with dialogue/action statistics. It is not afterwriting analytics. PDF
page count comes from independent PDF inspection, not a screenplay-length
estimate. Unsupported provider reports remain unavailable.

## Command and package boundary

The bin entry is `./awc.js`, a small Node loader rather than a standalone bundle.
The source-backed direct argument-vector form is:

```text
/absolute/path/to/node /absolute/path/to/afterwriting/awc.js --source source.fountain --pdf screenplay.pdf --config profile.json --overwrite
```

Use staged input/configuration and a fresh private output filename. Never build
a shell command. `--overwrite` removes the upstream interactive prompt; it does
not authorize replacing an existing user artifact. The Renderflow adapter uses
a guaranteed-new staged filename and omits that flag. Always provide an explicit
PDF filename instead of relying on the source-derived default.

The actual option parser exposes `--source`, `--pdf`, `--config`, `--overwrite`,
`--fonts`, and repeated `--setting`. It has **no provider `--version` and no
analysis/report flag**. The CLI emits a banner and progress logs, not JSON.
Read-only package identity inspection can check name/version/bin entry and
required files. A bounded Node version probe establishes only runtime identity;
it does not prove that afterwriting loads or renders.

The custom loader resolves project modules under `js/` and dependencies using
Node's ordinary module mechanism. Pinning only `awc.js` or `package.json` leaves
imported code and font metrics unpinned. Hash the complete adopted installation
tree, including dependencies and assets, and record the digest algorithm and
exclusions. `renderflow.package-files-json-sha256/v1` hashes the compact JSON
array of regular-file records sorted by their relative POSIX paths. Each record
contains `path`, `size_bytes`, and lowercase `sha256`, in that field order.
Root `.git` and `node_modules/.bin` directories are excluded; other symlinks and
special files are rejected. Empty directories do not affect the digest. A staged
snapshot prevents accidental writes to the original
installation. Node can search ancestor `node_modules` directories; clearing
`NODE_PATH` and global search paths alone does not establish a closed dependency
tree. Report loaded-code/source correspondence as unattested unless a separate
confinement mechanism establishes it. Tree hashing is not process isolation.

Use an absolute pinned Node executable, a cleared child environment, bounded
execution/capture/cancellation, and no automatic npm/npx/yarn/download path.
Record runtime version/hash, installed tree identity, source/config/argv/output
digests, profile ID, and independent validation. Missing runtime, package, or
required font metrics must fail before any successful artifact is published.

The adapter's `--no-addons` and `--no-global-search-paths` runtime options are
documented by the [Node command-line API](https://nodejs.org/api/cli.html).
They limit native-addon loading and global search paths; they do not prevent
ordinary ancestor-directory module resolution or make JavaScript a sandbox.
The exact declared Node 22/24 candidate version is separately pinned and
observed; that restriction is an authored profile, not a tested support matrix.

## Profile, input, and font findings

The script converter treats `<?xml` anywhere in input as an FDX conversion
request. Reject that marker even inside Fountain body text to avoid implicit
native import. Independently parse the supported body subset before invoking
afterwriting; unknown or ambiguous constructs must not be silently discarded.

Upstream defaults to A4, Courier Prime, title pages, page numbers, split dialogue,
and dual dialogue. Settings can suppress actions/dialogue/headings and replace
snippets. Unknown JSON settings are silently ignored. Generate controlled
configuration from a versioned Renderflow profile; do not forward arbitrary
JSON, `--setting`, snippets, or extra arguments. The selected first profile uses
A4 or US Letter, fixed Courier, no title page, visible page numbers, and no scene
numbers, with the other formatting switches explicitly bound by the adapter.

Active font loaders are Courier, CourierPrime, and CourierPrimeCyrillic. Kosugi
is listed in documentation and stored in the repository, but its loader entry
is commented out. Courier returns no custom font buffers, and the PDF writer
selects Courier, Courier-Bold, Courier-Oblique, and Courier-BoldOblique. These are
unembedded base-14 fonts. Printable ASCII is a deliberate first-profile limit,
not a claim of Unicode coverage or embedded-font fidelity. Viewer substitution
and typography remain unqualified. A request requiring embedding or another
font must be rejected rather than silently replaced.

CourierPrime loaders read generated JavaScript containing font data. The
`--fonts` path is also loaded through `require`, so it accepts executable code,
not merely a passive font. Custom fonts are outside this checkpoint.

PDFKit also requires its bundled AFM metrics for base-14 fonts. The neighboring
`v0.12.1` source's package entry is `js/pdfkit.js`; its build copies
`lib/font/data/*.afm` into `js/data`. The expected installed paths are therefore
`node_modules/pdfkit/js/data/Courier.afm`, `Courier-Bold.afm`,
`Courier-Oblique.afm`, and `Courier-BoldOblique.afm`; Helvetica metrics may also
be needed during document initialization. This path assessment is source-backed
but is not qualification of the locked `0.12.2` npm package.

## PDF and reproducibility

The writer creates a PDFKit document with compression disabled, A4 or Letter
paper, and zero library margins; its own profile places screenplay text. It
sets Title, Author, and Creator metadata but provides no creation-date/document-ID
override. No normalization option appears in its CLI/settings/controller. A
body-only profile disables the otherwise automatically created title page.

Supporting PDFKit evidence is available at `v0.12.1`, commit
`a5612c65c487554c5ce0d2d0f29c630735377a2e`: its document constructor creates
current-time metadata, and its security helper derives the ordinary document ID
from that metadata. This is **neighboring-version evidence, not verification of
locked `0.12.2`**; matching `v0.12.2`/`0.12.2` Git tags were unavailable. Do not
claim deterministic bytes, or attribute IDs to randomness, without actual
evidence. Retain original PDF bytes and report observed metadata and limitations.

Independent PDF inspection must be bounded and distinguish page structure,
dimensions, font policy, supported content, and text evidence from visual
quality. Structural/text inspection does not qualify clipping, pagination,
readability, printing, complete fidelity, or PDF/A conformance. Two identical
pinned native runs remain deferred; later record raw hashes and compare the
documented structural/content level while identifying metadata differences.

## Analysis assessment

Internal/browser statistics include scene and line counts, layout-derived page
estimates, timing estimates, characters, and locations. They depend on parser
settings and include internal token objects. Some divisions assume nonzero
dialogue or scene totals. The CLI provides no schema version, finite-number
contract, or JSON export. Do not scrape logs or inject JavaScript to access
private objects as if this were a proven public report capability. Any later
adoption needs a separate extraction, schema, bounds, fixtures, and validation
contract. The current Renderflow report remains independent and explicitly
limited to its own parsed subset and PDF evidence.
