- Corpus 1.3.0 adds a readable pinned original story file and `packs`/scenario
  case references to the existing v1 schemas and `golden_conformance` harness.
  It now has 31 source fixtures. There is no second test framework.
- `renderflow.document-fixture-pack/v1` is an embedded convention: pack/case
  IDs, document type, source/recipe/lock/profile/asset/rights pins, capabilities,
  parameters, expectations, validator IDs, typed availability and finite budgets.
  Only the selected comic subset is admitted; other types need explicit
  schema/recipe additions in the same harness.
- One source recipe creates original circle/square characters, a two-panel
  textless SVG per page, stable content/reading IDs, English content, licensed
  captured fonts and ordinary v2 build configurations. Editable input is distinct
  from measured outlined output. Review flags are synthetic declarations.
- Minimal case: two interior pages plus front/back covers; public native
  composition API plus a shared ordinary-build planning check. Five primary
  per-page candidates, actual publication/file joins, transcript/web semantics,
  decoded PNG geometry and independent bounded PDF geometry/image/pixel checks.
- Separate warm and cold first-page reruns assert reuse and deterministic
  candidate bytes. Source snapshots must remain unchanged. Optional new-directory
  retention copies generated source packages only, not passing output evidence.
- Larger case: the same parameters admit 44 ordered interior pages plus a
  separate two-page cover group. This tier is planning-only, with zero claimed
  output publications and explicit unavailable aggregate/EPUB mappings.
- Fourteen named negatives distinguish production typed content diagnostics,
  current unstructured loader errors, fixture-level order/count/geometry/alt
  assertions, cancellation, unavailable ORA with a transcript sibling and
  after-success payload absence/corruption.

## Review limits and remaining acceptance

Source inspection compared request/config/model fields, current loader errors,
font/registry paths, public planner/executor and verifier APIs, raster/PDF bounds,
the current print adapter and report/schema declarations. Hashes in the manifest
are authored source pins. No corpus generator/harness, tests, compiler/build/
Cargo, lint/format/schema/docs validators, CLI/native/provider/font/media/model
execution or CI ran. Nothing demonstrates that these new cases compile or pass.
No binary comic, visual golden baseline or passing report was produced.

Native composition emits RGBA PNG while ordered print requires RGB/grayscale;
no compatible normalizer/aggregation provider is selected. Combined interior
and cover PDF, comic EPUB, cover-wrap/spine/print conformance and actual provider
acceptance remain unavailable. The 44+2 case proves nothing about generated
outputs until an appropriately scoped future execution; it is not 44 distinct
story pages. Broader provider/version/process/font/script faults remain #412
coverage gaps. Existing legacy graph mocks never qualify these native routes.

Finite source/file/output and cooperative time guards are authored, not measured
performance, CI/memory sharding or sandbox guarantees. Human rights/content/
visual/accessibility/publication review and runtime/platform/release evidence
remain separate. #412/#413 and #429/#458/#419 stay open; private consumer comics
and Flow adapters are not needed to review this source checkpoint.
